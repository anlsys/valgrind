\section{Introduction}
%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%

% CONTEXT

\emph{Determinacy races} are concurrent programming hazards occuring when two accesses on the same memory address are not ordered, and at least one is writing~\cite{determinator}.
The presence of determinacy races in a program often hints correctness issues, as its output becomes non-deterministic given the same input.
With the ever growing intra-node parallelism in supercomputers, porting simulation codes while ensuring parallel execution correctness is challenging.
It is particularly true with asynchronous task-based programming models.

MOTIVATIONS

Existing determinacy race detectors mostly relies on LLVM'  ThreadSanitizer~\cite{thread-sanitizer} framework, which instruments programs at the compilation-time.
Such tool analysis can produce false-negative (\emph{i.e.} not reporting an determinacy race) by missing memory accesses occurring in uninstrumented code.

-> Heavyweight~\cite{valgrind}

OBJECTIVES

In this paper, we explore the use of heavyweight dynamic binary instrumentation towards determinacy race detections with no false-positive.

CONTRIBUTIONS

We introduce Taskgrind: a Valgrind tool for parallel programming model determinacy race detections.
We survey issues related to heavy instrumentations.
